# Домашнее задание: Улучшение RAG-системы — Hybrid Search (FTS) и Query Expansion

### 📌 Контекст и цель
В исходном репозитории [local-rag-mcp](https://github.com/MobilaName/local-rag-mcp) реализована базовая RAG-система на Python, работающая с локальной моделью семейства Qwen (0.6B–3B) и MCP-инструментами. 

Базовый RAG опирается только на векторный поиск (vector similarity search). Однако небольшие локальные LLM и векторные эмбеддинги часто теряют точность, если в запросе пользователя используются редкие термины, точные аббревиатуры или названия файлов/команд.

**Цель задания:** Увеличить точность и полноту (Recall/Precision) поиска RAG-системы за счет реализации **гибридного поиска** (Vector + Full-Text Search) и **предварительной генерации поисковых запросов/ключевых слов (Query Expansion)** с помощью LLM.

---

### 🎯 Задачи к выполнению

#### 1. Query Expansion & Keyword Generation (Генерация ключевых слов)
Добавьте шаг перед вызовом поиска:
- Сделайте предварительный запрос к LLM (Qwen) с просьбой извлечь ключевые слова/фразы из вопроса пользователя или предложить 2–3 альтернативных поисковых запроса.
- **Требование к промпту:** Учитывайте малый размер модели (0.6B–3B) — промпт должен быть максимально коротким и четким (желательно выводить ключевые слова через запятую или в формате простейшего JSON).
- Передавайте полученные ключевые слова и изначальный запрос в модуль поиска.

#### 2. Параллельный полнотекстовый поиск (FTS)
Реализуйте параллельный полнотекстовый поиск (Full-Text Search) поверх существующей базы документов:
- Добавьте FTS-индекс (можно использовать `rank_bm25`, `SQLite FTS5`).
- Настройте **параллельный запуск** векторного поиска и FTS (например, с использованием `asyncio.gather` или `ThreadPoolExecutor`), чтобы добавление FTS не увеличивало задержку (latency) приложения.

#### 3. Гибридное слияние результатов (Hybrid Fusion & RRF)
Объедините выдачу векторного и полнотекстового поиска:
- Реализуйте алгоритм **Reciprocal Rank Fusion (RRF)** или комбинацию скоров (Weighted Sum) для объединения двух списков найденных документов.
- Отберите `Top-K` наиболее релевантных чанков после объединения и передайте их в LLM для генерации финального ответа (или через MCP-инструмент).

#### 4. (Опционально / Дополнительные баллы) fallback при ошибках LLM
- Поскольку маленькая модель (0.6B–3B) может иногда отдать некорректный формат при генерации ключевых слов, реализуйте fallback-логику: если LLM не смогла вернуть ключевые слова, система должна использовать оригинальный текст запроса без падения программы.

### 💡 Подсказки 
- Для локальной Qwen (0.6B-3B) используйте `temperature=0` или `0.1` при генерации ключевых слов, чтобы уменьшить галлюцинации.
- Простейший RRF реализовывается формулой: $RRF\_Score(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$, где $k \approx 60$, а $r_m(d)$ — ранг документа в поиске $m$.
- Для FTS в Python отлично подходят `rank_bm25` (если документы в памяти) или `sqlite3` с таблицей `MATCH / FTS5` (если храните на диске).
